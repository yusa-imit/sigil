# Plan 001 — Zig 0.16 migration and Tiger Style baseline

## Goal

Put sigil on Zig 0.16.0 end to end (source, manifest, CI), stand up a machine-enforced Tiger Style
`tidy` step, and settle the kingdom's `io: Io` convention here — sigil is the spike, so the shape
decided now is what the other eight realms copy. Ship 0.2.0 in the manifest and `CHANGELOG.md`, no
tag.

## Why now

sigil is the cheapest place to make every kingdom-wide mistake: the probe found **1** error on
0.16 (`GeneralPurposeAllocator` at `src/main.zig:7`) and `zig test src/root.zig` — the whole
library surface — already passes clean, which is why `citadel/docs/ROADMAP.md` makes it the spike.
Guardrails are also free only now: at 285 LOC of stubs, `tidy` and the assertion baseline are
written before there is code to retrofit them onto, so Phase 1A starts on a green 0.16 build.

- [x] **`io: Io` convention on the public API (kingdom spike).** `blocked_by: none`. Pinned as
      `config.load(comptime T: type, io: Io, arena: Allocator, options: Options) LoadError!T` and
      the `json.parseFile`/`stringifyFile` shape (the representative format module; a comptime
      parity test in `src/root.zig` binds toml/yaml/msgpack/cbor/proto/csv to the same shape the
      day they add it). Rule pinned: `comptime T` occupies the receiver slot, so `io` is the
      second parameter of a generic free function; `Io.Dir`/env/argv are always explicit, never
      read by sigil itself; libraries never construct an `Io`. **Two deviations from this item's
      literal sketch**, argued in `docs/adr/0001-io-convention.md`: the allocator parameter is
      named `arena` (not `gpa`) because `load` never frees — the name states the ownership
      contract per Tiger Style §3.8; `config.watch(io, path, cb)` became a poll-based
      `config.Watcher.poll(io) !?Change` instead of a callback, because Tiger Style §1.14 bans
      running user code from inside an I/O completion and 0.16's `std.Io` has no watch primitive
      to hook into anyway (a rate-limited `Io.Dir.statFile` sweep is a poll by construction).
      Error sets are hand-written per function, unioned with the existing `error{NotImplemented}`
      stub, not composed from std's I/O error sets. Verify: `zig build test`, `zig fmt --check`,

## Risks

- **Zero functional coverage.** 11 of 12 tests are `refAllDecls` compile checks, so a migration
  regression would be invisible; the probe count is a floor (Zig stops each unit at its first
  error), so `main.zig` may hide a second break. Mitigation: every migration item verifies with a
  build or a run, not a grep; the CLI gets a smoke test.
- **All-zero Tiger Style metrics are a non-finding**, not a clean bill: 285 LOC of stubs has no
  loop or allocation to violate. Mitigation: `tidy` and the assertion warning land now, cheaply.
- **README overstates the library**; a consumer would expect a working JSON parser. Mitigation:
  the README item — and no tag exists to `zig fetch` anyway.
- **The spike locks a convention in for eight realms** — a wrong `io: Io` shape is cheap here,
  expensive in sailor. Mitigation: exercise it against `std.testing.io` and `Io.failing` first.
- **CI's macOS exclusion may be stale** (a 0.15 libSystem link bug); the CI item re-tests it.
